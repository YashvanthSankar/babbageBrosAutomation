# Manual demo controls and dashboard copy · 2026-10-09

The latest Downloads image showed separate call-your-number and email-your-address example panels. Git history did not contain that precise combination: the earlier voice control (`c27fc99`) was deleted in `6d5336f`; the later typed-address email control (`5a3915b`) was restricted in `32a929e`. Neither old arbitrary-recipient endpoint is appropriate for a public demo whose credentials accept any nonempty password. The image does not establish that either provider delivered a message or connected a call.

Restored the two understandable example panels without the old dispatch behavior. Both use fixed synthetic 69% attendance, simulate unless the VPS explicitly opts into live delivery, and reject typed contacts other than the server-pinned consenting test contact. The email route retains its durable once-per-day claim. The new professor-only `POST /api/voice/demo-call` uses the existing OmniDimension adapter but **always** dispatches to `DEMO_AUTOMATION_PHONE`, never the request body, after a separate atomic once-per-day claim. An absent/invalid live recipient or provider configuration fails before claiming. Provider acceptance is not delivery/answered-call proof. The new route is local only until VPS deployment; there was no real provider call during this change.

Dashboard audit: corrected the landing-page claim of a preview within the one-shot faculty import UI (the staged preview API still exists), gave the student view a distinct no-results status, clarified summary/table/roster wording, stopped treating unavailable or unrecognized automation status as proof of simulation, labeled manual and weekly activity clearly, and exposed Sign out on narrow faculty screens. Kept the existing faculty overview, imports, risk filters, booking and activity structure rather than rebuilding it.

New voice-route tests cover professor authorization, recipient restriction, simulation, pinned live dispatch, missing configuration, provider failure and duplicate claims.
