## What is implemented

- NextAuth (JWT sessions) with **two Google providers**:
  - `google` — students, scopes `openid email profile` only.
  - `google-professor` — professor, scopes `openid email profile
    https://www.googleapis.com/auth/calendar.freebusy
    https://www.googleapis.com/auth/calendar.events` with `access_type=offline`,
    `prompt=consent`.
  - The `google-professor` provider is reserved for the exact `PROFESSOR_EMAIL`;
    students cannot use it, so they are never asked for calendar permissions.
  - Authorization: admin = exact `PROFESSOR_EMAIL` (never inferred from domain);
    student = Google-verified `@iiitdm.ac.in` email **and** present in the roster
    (`students.email`). Non-roster students are denied at sign-in.
- Professor refresh token persisted **encrypted server-side** (AES-256-GCM) in
  `oauth_tokens`; it is never put in the JWT or returned to a client. Key derived
  from `TOKEN_ENCRYPTION_KEY` (preferred) or `NEXTAUTH_SECRET`.
- `GET /api/dashboard` — session-scoped; admin sees all students of the professor,
  student sees only their own record. Real attendance risk, `classesToRecover`,
  latest/previous comparable marks and a trend. **No phone numbers returned.**
- `GET /api/calendar/slots` — 30-min candidate slots (configurable) in the
  professor time zone, returned as ISO UTC, merged from Google FreeBusy + local
  bookings. Honest fallback when Google is not connected.
- `POST /api/calendar/book` — server-derived student, subject/ownership checks,
  live free/busy revalidation, and a transactional reservation
  (`pg_advisory_xact_lock(hashtext(professor_email))` + overlap check) so a slot
  cannot be double-booked. Calendar event created on the professor's primary
  calendar; on Google failure the reservation is marked `failed` and never blocks.

## Database schema (`db/schema.sql`)

Run before any import: `psql "$DATABASE_URL" -f db/schema.sql` (idempotent).

Backend-owned tables:

- `students(id, name, roll_no UNIQUE, email UNIQUE lowercase, phone, professor_email, created_at, updated_at)`
- `subjects(id, name, code, professor_email, department, created_at, updated_at)` — `UNIQUE(professor_email, code)`
- `attendance_records(id, student_id, subject_id, class_date DATE, present BOOLEAN, ...)` — `UNIQUE(student_id, subject_id, class_date)` (re-import must upsert)
- `test_results(id, student_id, subject_id, test_name, test_date DATE, score NUMERIC(6,2), max_score NUMERIC(6,2), ...)` — `UNIQUE(student_id, subject_id, test_name, test_date)`; percentages computed at read time
- `bookings(id, student_id, subject_id, professor_email, starts_at TIMESTAMPTZ, ends_at TIMESTAMPTZ, google_event_id, status, ...)` — status in `pending|confirmed|cancelled|failed`
- `oauth_tokens(id, email, provider, refresh_token_encrypted, scope, token_type, expires_at, ...)` — professor calendar token, encrypted

**Voice teammate:** `notification_events` is provisioned in the same file so the
schema is complete: `(id, student_id, subject_id, idempotency_key UNIQUE,
risk_level, provider, status default 'pending', created_at, sent_at)`. Use exactly
these columns; I will not change them without agreement.

All foreign keys cascade on student/subject delete. Emails are constrained to
lowercase. Numeric marks are `NUMERIC(6,2)` (pg returns them as strings; the
dashboard casts to `float8`).

## API contract notes

- Success responses return the contract object directly (dashboard object,
  `{ slots: [...] }`, `{ booking: { id, start, end, status, eventId } }`).
- Errors are always `{ error: { code, message, details? } }`.
- Error codes: `UNAUTHENTICATED` 401, `FORBIDDEN`/`NOT_IN_ROSTER` 403,
  `INVALID_*` 400, `SUBJECT_NOT_FOUND` 404, `SLOT_UNAVAILABLE` 409,
  `DB_NOT_CONFIGURED`/`CALENDAR_NOT_CONFIGURED`/`CALENDAR_AUTH_REQUIRED`/
  `CALENDAR_UNAVAILABLE` 503, `CALENDAR_API_ERROR` 502, `INTERNAL_ERROR` 500.
- Dashboard `stats` shape: `{ students, subjects, atRisk }`.
- Dashboard subject extra field: `latestTestName`. `latestScore`/`previousScore`
  are **percentages** (comparable), not raw marks.
- Student `subjects` lists all of the professor's subjects (zeros when the
  student has no data for one), so the shape is stable.
- Slots response adds `date`, `timeZone`, `source: "google" | "local"`,
  `calendarConnected: boolean`, and an optional `warning` when Google is
  unavailable. When `calendarConnected` is false the UI must present availability
  as local-only, not as the real calendar.
- Booking is rejected with `503 CALENDAR_UNAVAILABLE` if the professor has not
  connected Google Calendar (honest: we do not create events we cannot verify).

## Environment

Required: `DATABASE_URL`, `NEXTAUTH_URL`, `NEXTAUTH_SECRET`, `GOOGLE_CLIENT_ID`,
`GOOGLE_CLIENT_SECRET`, `PROFESSOR_EMAIL`.

Recommended: `TOKEN_ENCRYPTION_KEY` (separate from `NEXTAUTH_SECRET`).

Optional calendar tuning: `CALENDAR_TIMEZONE` (default `Asia/Kolkata`),
`CALENDAR_WORKDAY_START`/`CALENDAR_WORKDAY_END` (default `09:00`/`17:00`),
`CALENDAR_SLOT_MINUTES` (default `30`), `CALENDAR_MIN_BOOKING_MINUTES` /
`CALENDAR_MAX_BOOKING_MINUTES` (default `20`/`30`), `DATABASE_SSL=true` or
`PGSSLMODE=require` for managed Postgres.
