# OmniDimension voice calls — 2026-10-08

- Added the server-only OmniDimension dispatch client at `lib/voice/omnidim.ts`. It uses `OMNIDIM_API_KEY`, `OMNIDIM_AGENT_ID`, and `OMNIDIM_FROM_NUMBER_ID` from the server environment; no credential belongs in source control or client code.
- Added `POST /api/voice/call` for a professor/admin manual call. Its body is only `{ "studentId": number, "subjectId": number }`; it derives the professor ownership, phone number, attendance and threshold from PostgreSQL. It accepts only valid Indian E.164 mobile numbers and never exposes the phone back to a student.
- The service records a `notification_events` row before dispatch and uses an attendance-snapshot idempotency key. An unchanged upload/manual retry cannot place a second call. Provider errors are recorded as `failed`.
- Attendance ingestion snapshots each touched student's pre-import risk and invokes `dispatchAtRiskAttendanceCall` only when that student newly crosses below the subject threshold. It never triggers on a dashboard GET or an unchanged import.
